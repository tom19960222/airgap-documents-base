# User Guide

> **Note:**
>
> **Making Open Source More Inclusive**
>
> Red Hat is committed to replacing problematic language in our code, documentation, and web properties. We are beginning with these four terms: master, slave, blacklist, and whitelist. We ask that you open an issue or pull request if you come upon a term that we have missed. For more details, see [our CTO Chris Wright’s message](https://www.redhat.com/en/blog/making-open-source-more-inclusive-eradicating-problematic-language).

Welcome to the Ansible User Guide! This guide covers how to work with Ansible, including using the command line, working with inventory, interacting with data, writing tasks, plays, and playbooks; executing playbooks, and reference materials.
Quickly find answers in the following sections or expand the table of contents below to scroll through all resources.

## Writing tasks, plays, and playbooks

- I’m writing my first playbook. What should I [know before I begin](playbooks_best_practices.md#playbooks-tips-and-tricks)?
- I have a specific use case for a task or play:

  - Executing tasks with elevated privileges or as a different user with [become](become.md#become)
  - Repeating a task once for each item in a list with [loops](playbooks_loops.md#playbooks-loops)
  - Executing tasks on a different machine with [delegation](playbooks_delegation.md#playbooks-delegation)
  - Running tasks only when certain conditions apply with [conditionals](playbooks_conditionals.md#playbooks-conditionals) and evaluating conditions with [tests](playbooks_tests.md#playbooks-tests)
  - Grouping a set of tasks together with [blocks](playbooks_blocks.md#playbooks-blocks)
  - Running tasks only when something has changed with [handlers](playbooks_handlers.md#handlers)
  - Changing the way Ansible [handles failures](playbooks_error_handling.md#playbooks-error-handling)
  - Setting remote [environment values](playbooks_environment.md#playbooks-environment)
- I want to take advantage of the power of re-usable Ansible artifacts. How do I create re-usable [files](playbooks_reuse.md#playbooks-reuse) and [roles](playbooks_reuse_roles.md#playbooks-reuse-roles)?
- I need to incorporate one file or playbook inside another. What is the difference between [including and importing](playbooks_reuse.md#dynamic-vs-static)?
- I want to run selected parts of my playbook. How do I add and use [tags](playbooks_tags.md#tags)?

## Working with inventory

- I have a list of servers and devices I want to automate. How do I create [inventory](intro_inventory.md#intro-inventory) to track them?
- I use cloud services and constantly have servers and devices starting and stopping. How do I track them using [dynamic inventory](intro_dynamic_inventory.md#intro-dynamic-inventory)?
- I want to automate specific sub-sets of my inventory. How do I use [patterns](intro_patterns.md#intro-patterns)?

## Interacting with data

- I want to use a single playbook against multiple systems with different attributes. How do I use [variables](playbooks_variables.md#playbooks-variables) to handle the differences?
- I want to retrieve data about my systems. How do I access [Ansible facts](playbooks_vars_facts.md#vars-and-facts)?
- I need to access sensitive data like passwords with Ansible. How can I protect that data with [Ansible vault](vault.md#vault)?
- I want to change the data I have, so I can use it in a task. How do I use [filters](playbooks_filters.md#playbooks-filters) to transform my data?
- I need to retrieve data from an external datastore. How do I use [lookups](playbooks_lookups.md#playbooks-lookups) to access databases and APIs?
- I want to ask playbook users to supply data. How do I get user input with [prompts](playbooks_prompts.md#playbooks-prompts)?
- I use certain modules frequently. How do I streamline my inventory and playbooks by [setting default values for module parameters](playbooks_module_defaults.md#module-defaults)?

- Controlling how my playbook executes with [strategies and more](playbooks_strategies.md#playbooks-strategies)
