# Istio 1.24 官方文件來源研究

## 結論

本批匯入 Istio 1.24 文件的官方來源為
[`istio/istio.io`](https://github.com/istio/istio.io)，固定在 immutable commit
[`34199a22213d0bbfe10ab1759d89242ee752ac12`](https://github.com/istio/istio.io/commit/34199a22213d0bbfe10ab1759d89242ee752ac12)。
manifest 不含 `.git`，使用 `shortcode_profile = "istio"` 驅動共用 Hugo
shortcode normalizer；實際 fetch 與 normalize 後產生 385 個 output page，沒有
output page 遺失或 basename collision；其中 45 頁是刻意保留的 section-index
source page 沒有正文，但透過 manifest opt-in 的 description fallback 仍保留
可索引 body（不是遺漏正文）。

這份 corpus 代表 upstream Istio 1.24 文件。環境中的
`istio 1.24.0-custom-v2` 只映射到這份 upstream base 1.24 文件，不宣稱
custom patch 有對應的 upstream 文件或相同的行為。

page 與 provenance 必須保留；normalize 僅在 manifest opt-in 時把原始
description 同時保留於 frontmatter，並在 body 為空時以該 description 作為
body fallback，不捏造非來源內容。

## Shortcode inventory 與轉換策略

inventory 以固定 checkout 的 385 個 Markdown source file 掃描 Hugo
`{{< ... >}}`／`{{% ... %}}` token；delimiter scan 共看到 6,609 個
`{{<`／`{{%`，其中包含文件中以 Hugo comment 形式展示的 65 個 shortcode
範例，以及少數巢狀／不完整 token。normalize 後 executable shortcode residual
為 0；corpus 仍保留 25 個刻意保護的 literal delimiter（21 個 inline-code
範例、4 個 escaped tutorial shortcode），符合 code fence／inline literal 不改寫
與 escaped teaching syntax 可讀保留的規則。
normalizer 使用可處理巢狀參數的 scanner，不以 regex 截斷有用內文。主要 paired shortcode
的 open／close 數量如下：

| shortcode | open | close | 轉換方式 |
| --- | ---: | ---: | --- |
| `text` | 2,142 | 2,142 | fenced code block，保留語言與內容 |
| `tabset` | 138 | 138 | 保留 category 與 tab 內容 |
| `tab` | 281 | 281 | `**Tab: 標題**` 加上內容 |
| `warning` | 126 | 126 | readable admonition |
| `tip` | 187 | 187 | readable admonition |
| `idea` | 10 | 10 | readable admonition |
| `quote` | 3 | 3 | readable admonition |
| `gloss` | 149 | 151 | 保留 term／內文；不丟棄文字 |
| `image` | 123 | 0 | Markdown image；caption 轉 alt/title 可讀文字 |
| `boilerplate` | 107 | 0 | 僅從 repo 內 `content/en/boilerplates` 安全內嵌 |
| `text_import` | 4 | 0 | 僅從 repo 內相對路徑讀取並 fenced |

另有 Istio 版本、GitHub source、icon、Mermaid 與 Kubernetes 版本等
single-line shortcode。未知 shortcode 會保留可讀的 `[name args]` marker；
generic paired／closing tag 會保留內文，unmatched closing tag 只丟棄該 tag，
不會吞掉後面的普通範例文字。Hugo comment 與 escaped shortcode 範例會轉成
可讀文字或移除 comment，不會把 raw template 帶入 corpus。

`boilerplate` 與 `include` 都必須是 repo-relative path，並以 resolved path
確認仍位於允許的 repository／boilerplates root；absolute path、`..` 越界、
recursive self-reference 都不會讀取。這個安全邊界也有 regression test。

Kubernetes 仍使用既有 implicit profile，`clean_hugo_shortcodes` 的既有結果
由 regression test 固定；manifest 指定不存在的 profile 會 unknown fail-fast、明確
raise `ValueError`；目前列出的 profile 為 `kubernetes`、`istio`、`gitbook`、
`prometheus-operator`。

## Provenance、links 與驗證

每一頁 front matter 的 `collection`、`version`、`title`、`fetched_at`、
`source_url` 與 manifest 指定的 `app_version: "1.24.0"` 均由 manifest 與
raw checkout metadata 產生；docs `source_url` 使用固定 40 字 commit：

```text
https://github.com/istio/istio.io/blob/34199a22213d0bbfe10ab1759d89242ee752ac12/<path>
```

`github_tree`、`github_blob`、`github_file` shortcode 不是
`istio/istio.io` 的文件頁連結，而是 application repository source link；其輸出
分別固定到 `https://github.com/istio/istio/tree/8825a6b7f8c9a2d66005a5f8b64e98aaee0dda99/…`、
`https://github.com/istio/istio/blob/8825a6b7f8c9a2d66005a5f8b64e98aaee0dda99/…`、
`https://raw.githubusercontent.com/istio/istio/8825a6b7f8c9a2d66005a5f8b64e98aaee0dda99/…`；
`istio_release_url` 固定為 [`Istio 1.24.0 release`](https://github.com/istio/istio/releases/tag/1.24.0)。
文件中以 `{{</* github_file */>}}` 等 escaped 形式示範 shortcode 的頁面維持可讀
marker，不轉成 application URL。

已實際執行：

```shell
python3 builder/git_source.py fetch builder/manifests/istio-1.24.toml
python3 builder/git_source.py normalize builder/manifests/istio-1.24.toml
python3 builder/validate_ceph_corpus.py \
  --manifest builder/manifests/istio-1.24.toml \
  --corpus-dir corpus/istio/1.24 \
  --raw-repo raw/istio/1.24/repo --json
```

validator 結果為 `page_count=385`、`raw_source_count=385`、
`raw_nonempty_count=385`、`expected_page_count=385`、`pinned_asset_links=128`、
`unresolved_refs={}`、`unresolved_link_markers={site: 196}`、
`unresolved_source_links=0`、`failures=[]`。可映射的 Istio `/docs` route 已改為
corpus-relative link 並保留 query/fragment；找不到 corpus page 的 `/docs` route
與 `/blog`、`/about`、`/news`、`/get-involved`、`/archive` 等 scope 外 route
改為 `https://istio.io/v1.24/...` 並附 `unresolved-site-link` marker。這些 marker
讓 scope 外連結可計數且不會被 validator 靜默忽略；沒有把它們偽造為離線頁面。

全量 residual scan 顯示 normalized corpus 的 executable Hugo shortcode opening
delimiter、Hugo comment 均為 0；另有前述 25 個刻意保留的 inline／escaped
teaching literal。抽查 `text`、`tabset`／`tab`、`boilerplate`、admonition 與
multiline `image` 頁面均保留正文與可讀輸出。固定來源不是 Liquid/Jekyll 文件，
因此沒有把非本來源的 Liquid/Jekyll 語法當成 Istio shortcode 處理。

本次 Istio 變更已完成 `compileall`、Istio validator、shortcode、route、description
的離線 smoke checks，並以專案既有 virtualenv 跑完整 builder 74 tests 與 runtime
5 tests，全部通過。完整 index 實測本批 385 頁產生 1,667 chunks、0 個 0-chunk
page；全庫 full build 為 35,291 頁、300,450 chunks，後續兩次 incremental build
皆為 0 變更。
