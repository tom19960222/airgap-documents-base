# Python 3.10 標準函式庫文件來源研究

## 結論

新增一份 collection `python`、version `3.10.21` 的 corpus，內容是 Python 3.10 線
最新 patch release 的**所有內建（標準函式庫）模組文件**。來源是官方
[docs.python.org](https://docs.python.org/3.10/) 的 rendered HTML，透過 BFS crawl
發現頁面，再由同一份 raw HTML archive 正規化成 Markdown；raw archive 不提交，
只有 `corpus/` 與 manifest 進入版本控制。

範圍是「模組文件」而不是整份 Python 文件：`library/`（The Python Standard
Library，所有內建模組的文件本體）與 `distutils/`（3.10 仍在標準函式庫內、但
API reference 放在 `library/` 之外的唯一模組群）。tutorial、language reference、
C API、HOWTO、FAQ、whatsnew 不是模組文件，不在這次範圍內。

## 版本判定

| 項目 | 值 | 依據 |
| --- | --- | --- |
| 3.10 線最新 patch | 3.10.21（2026-08-13 發布） | [endoflife.date/python](https://endoflife.date/api/python.json)；3.10 的 EOL 為 2026-10-31 |
| corpus version | `3.10.21` | 抓取當下 `https://docs.python.org/3.10/` 每頁 `<title>` 自述為「Python 3.10.21 documentation」 |

官方文件站沒有 per-patch 的 URL：`/3.10/` 是以 3.10 維護分支持續重建的路徑，
不是固定 tag。因此這份 corpus 的版本邊界是「抓取當下 `/3.10/` 的建置」，其
自述 release 為 3.10.21。抓取後如果上游又發 3.10.22 並重建，`/3.10/` 會跟著變，
但已落盤的 corpus 仍然只代表 3.10.21 這次建置，frontmatter 的 `source_url` 也
固定在 `/3.10/` 命名空間，不會混進 3.9、3.11 或 `/3/`（rolling）版本。

沒有改用 cpython repo 的 `v3.10.21` tag（`Doc/` 下的 reST）作為來源：那份是
Sphinx 原始碼，內建模組的簽章與交叉引用要經過 Sphinx 才會展開，直接轉 Markdown
會留下大量未解析的 domain directive。官方站的 rendered HTML 是同一份文件展開後
的結果，對離線檢索更直接。

## 為這批來源做的建置端修正

三項都在建置端，corpus 內容是修正後的產出。

### 1. crawl：依文件宣告的編碼解讀回應

docs.python.org 只送 `content-type: text/html`，不帶 charset。HTTP 1.1 對這種
`text/*` 的預設值是 ISO-8859-1，requests 也照做，於是整份 UTF-8 文件被當成
Latin-1 解讀：`os — Miscellaneous...` 變成 `os â Miscellaneous...`，而且會
原封不動存進 raw archive。`crawl.py` 改成 header 有標 charset 時相信 header，
否則採用 HTML 自己宣告的 `<meta charset>`，再退回 requests 的內容偵測。

這是第一個沒有標 charset 的來源：重新檢查既有 corpus（tocas、ubuntu、kernel、
ceph、gitlab、netbox、opensearch）沒有對應的 mojibake，OpenSearch 語料中的
`român` 等字是文件本身的羅馬尼亞文範例。因此這次修正不影響任何既有 collection，
也不需要重抓。發現當下 corpus 已受影響的 318 個檔案已在修正後整批重抓重建。

### 2. manifest：`allow_prefixes`

`common.in_scope()` 新增 fail-closed 的 allowlist：非空時只有列出的 prefix 在
範圍內，空值維持既有行為（`base_url` 底下除 `deny_prefixes` 以外全收）。
base page 本身永遠在範圍內，crawl 才有起點。用 allowlist 而不是把其餘章節列成
`deny_prefixes`，是因為漏列一個 deny prefix 會讓 crawl 溢出到整份 Python 文件，
而漏列 allow prefix 只會少收、看得出來。

### 3. normalize：合併簽章、拆掉標題的 self-link

兩項都只對 `python` collection 生效，不改動其他 collection 的既有產出。

- **簽章合併**：Sphinx 的 py-domain 簽章由多個相鄰節點組成（`sig-prename`、
  `sig-name`、`sig-paren`、`sig-param`…），逐節點轉換會得到
  `` `os.``getcwd`() `` 這種被切斷的字串，grep baseline 搜 `os.getcwd` 找不到
  任何一頁。改以 Sphinx 自己渲染出來的文字重建整段簽章，輸出
  `` `os.getcwd()` ``、`` `os.utime(path, times=None, *, [ns, ]dir_fd=None, follow_symlinks=True)` ``、
  `` `exception os.error` ``、`` `class os.PathLike` ``。全 corpus 已無殘留的
  切斷簽章（0 處）。
- **標題 self-link**：幾乎每頁的 h1 都是指向同一頁 module 錨點的 self-link，
  轉成 Markdown 後標題會變成
  `` # [`os`](os.md#module-os "os: ...") — ... ``，讓 runtime 切段後的 section
  path 夾帶整段連結語法。改成只拆掉 target 是本頁的連結（426 處 → 0 處），
  指向其他頁的標題連結（22 處，例如 multiprocessing 的「Shared `ctypes` Objects」）
  保持原樣。

建置端回歸測試同步新增 `builder/tests/test_crawl_encoding.py`（4 tests）、
`builder/tests/test_url_scope.py`（5 tests）、
`builder/tests/test_html_normalizer.py`（4 tests）。
