# Python 3.12 標準庫文件來源研究

## 結論

新增一份 collection `python`、version `3.12.14` 的 corpus，內容是官方
[The Python Standard Library](https://docs.python.org/3.12/library/) 全部頁面：
內建函式、內建型別、例外，以及官方 module index 列出的 309 個標準庫模組。來源是
docs.python.org 的 `3.12/library/` rendered HTML，經既有的 crawl → normalize
流程轉成 Markdown；raw archive 不進版本控制，只有 `corpus/` 與 manifest 進 git。

同一天另有一份 [Python 3.10.21 corpus](2026-09-17-python-3.10-stdlib-source.md)
（PR #9）落地，兩者同屬 collection `python`、以 version 區隔；本頁只描述 3.12。
兩份是各自獨立作業，builder 的共用修正在合併時統一成一套實作（見下節）。

版本以 `3.12.14` 記錄。docs.python.org 只以 major.minor 發佈文件樹（`/3.12/`），
內容跟著 3.12 分支持續重建；抓取當日該文件樹頁尾標示的版本是
`Python 3.12.14 documentation`，3.12 系列當日最新的 patch release 也是
[3.12.14](https://www.python.org/downloads/release/python-31214/)（2026-08-12），
兩者一致，因此如實記為 3.12.14 而不是 `3.12`。這代表之後 3.12.15 發佈時，同一個
URL 會改建成新版內容；要更新就重跑 crawl 並改 manifest 的 `version`。

範圍只收 `library/`。tutorial、language reference、c-api、howto、using、FAQ 不在
這次需求（「所有內建模組的文件」）內，指向這些區塊的連結保留絕對 URL，離線環境
點不開，但不會被誤認成已收錄的本地文件。

## 官方來源與版本邊界

| collection | version | 官方來源 | manifest | 文件邊界 |
| --- | --- | --- | --- | --- |
| python | 3.12.14 | [The Python Standard Library（3.12）](https://docs.python.org/3.12/library/) | [`python-3.12.toml`](../../builder/manifests/python-3.12.toml) | `docs.python.org/3.12/library/` 之下的全部頁面；不含 tutorial / reference / c-api / howto，也不延伸到 `3.11`、`3.13` 或 `/3/`（rolling alias） |

3.12 沒有 `distutils/`（該模組在 3.12 移除），所以 `base_url` 直接指到
`library/`，不需要 3.10 manifest 用的 `allow_prefixes`。`content_selector` 與
3.10 manifest 一致採用 `div.body[role=main]`。

以官方 [module index](https://docs.python.org/3.12/py-modindex.html) 對照覆蓋率：
該頁列出 309 個模組，全部指向 `library/` 之下的 258 個頁面，這 258 頁在 corpus
中都存在，沒有缺頁；沒有任何模組是記在 `library/` 以外的區塊。

corpus 內有 5 個指向 `docs.python.org/3.11/library/` 的連結，分別在
`smtpd.md`、`distutils.md`、`imp.md`、`asynchat.md`、`asyncore.md`：這是上游 3.12
文件自己在「模組已於 3.12 移除，舊文件見 3.11」處寫的跨版本指引。它們保留成外部
絕對 URL，沒有把 3.11 的頁面抓進 3.12 corpus，frontmatter 的 `source_url`
100% 落在 `https://docs.python.org/3.12/library/`。

## builder 修正與合併結果

這份 corpus 抓取過程中遇到兩個 builder 問題，3.10 那份（PR #9，先合併進 main）
獨立遇到並修掉了同樣兩個。合併時保留 main 既有的實作，刪掉本分支的重複版本，
避免同一件事有兩套程式：

| 問題 | 採用的實作 | 本分支原本的重複實作 |
| --- | --- | --- |
| docs.python.org 只送不帶 charset 的 `Content-Type: text/html`，requests 依 RFC 2616 退回 ISO-8859-1，整份 UTF-8 文件變 mojibake 並存進 raw archive | main 的 `crawl.response_text()`（header charset → 文件 meta charset → requests 內容偵測） | `crawl.decode_html()`，已刪除 |
| Sphinx 模組頁 h1 指向自己的 module target、docutils `contents` 的 backref，讓 Markdown 標題變成自我連結並污染索引的 `section_path` | main 的 `normalize.unwrap_self_links_in_headings()`（以 canonical URL 比對，只拆本頁 target，限 `python` collection） | `clean()` 內比對 `href` 開頭 `#` 的版本，已刪除 |

mojibake 的具體症狀：第一次抓完的 `os.path.md` 標題裡，原文的 em dash `—`
（U+2014，UTF-8 為 `e2 80 94`）變成三個 Latin-1 字元 U+00E2、U+0080、U+0094。
raw archive 存的就是錯誤解碼後再編碼的 bytes，所以不是 normalize 的問題；修正
後重抓全部 321 頁。以這類錯誤解碼的指紋（U+0080〜U+009F C1 控制字元）掃描全部
35,934 個 corpus Markdown（含 3.10 與 3.12），命中 0 個檔案。

自我連結標題在修正前有 89 個，修正後 0 個；唯一一個跨頁的標題連結
（`email.examples.md` 的 `# [`email`](email.md#module-email …)`）依規則保留。

本分支實際新增的 builder 修改只有一項：`normalize.merge_sphinx_signatures()`
原本只認 `code.descname` / `code.sig-name`，那是 3.10 文件的 Sphinx 版本產生的
標記；3.12 文件改用 `span`（`<span class="sig-name descname">`），簽章因此沒有
被合併成單一 inline code。選擇器補上 `span.descname` / `span.sig-name` 後，
3.12 的 `os.getcwd()` 與 3.10 一樣輸出成 `` `os.getcwd()` ``，同一個 collection
的兩個版本格式一致。3.10 的 `dt` 本來就由 `code` 選擇器命中，輸出不變（已確認
兩份 corpus 都沒有被切斷的 `` `os.``getcwd` `` 簽章）。這項修改在
`builder/tests/test_html_normalizer.py` 補了一個 span 標記的測例。

## 靜態驗證與殘留項目

全量檢查 320 個 Markdown：

- frontmatter：`collection`、`version`、`title`、`source_url`、`fetched_at` 全部
  存在且格式正確，`bad_frontmatter = 0`；`version` 全為 `3.12.14`，`source_url`
  全在 3.12 `library/` 之下，重複 `source_url` 0 筆。
- 正文長度：沒有任何頁面正文短於 200 字元（沒有只剩標題的空殼頁）。
- 導覽模板殘留：`<nav>`、`headerlink` 皆 0。`<script`／`<style`
  各命中 1 個檔案（`html.parser.md`，是 HTMLParser 文件在說明這兩個標籤）、
  `Navigation` 命中 2 個（`idle.md`、`tk.md` 的 IDLE/Tk 功能說明）、
  `Table of Contents` 命中 1 個（`idle.md`），都是正文內容不是 chrome。
- 空白與控制字元：trailing-space 行 0、NUL 0。
- code fence 共 3,010 個，其中 1,710 個沒有語言標記（上游 Sphinx 標為
  `default`/`none`），其餘主要是 `python3`（1,078）、`pycon`（87）、
  `shell-session`（52）。

連結檢查：22,706 個相對連結、3,621 個絕對連結。相對連結中 22 個 target 在 corpus
內不存在，分成兩類，兩類都不是漏頁：

- 5 個是刻意不收的圖片 asset（`hashlib`、`pathlib`、`statistics`、
  `tkinter.messagebox`、`turtle` 各 1 張 PNG）。corpus 邊界是純文字 Markdown，
  沒有下載圖片／CSS／JS。
- 17 個在 `typing.md`，是 fenced code block 內 PEP 695 泛型語法
  （例如 `def first[T](l: Sequence[T]) -> T:`）剛好符合 Markdown 連結語法的
  誤判，不是真的連結。

絕對連結中指向 docs.python.org 其他區塊的共 2,045 個（reference 846、
glossary 842、using 177、c-api 81、howto 58、tutorial 20 等），是本次範圍外的
官方頁面；離線環境無法開啟，但版本都固定在 `/3.12/`，不會指到 rolling `/3/`。
