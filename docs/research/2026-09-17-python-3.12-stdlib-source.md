# Python 3.12 標準庫文件來源研究

## 結論

新增一份 collection `python`、version `3.12.14` 的 corpus，內容是官方
[The Python Standard Library](https://docs.python.org/3.12/library/) 全部頁面：
內建函式、內建型別、例外，以及官方 module index 列出的 309 個標準庫模組。來源是
docs.python.org 的 `3.12/library/` rendered HTML，經既有的 crawl → normalize
流程轉成 Markdown；raw archive 不進版本控制，只有 `corpus/` 與 manifest 進 git。

版本以 `3.12.14` 記錄。docs.python.org 只以 major.minor 發佈文件樹（`/3.12/`），
內容跟著 3.12 分支持續重建；抓取當日該文件樹頁尾標示的版本是
`Python 3.12.14 documentation`，3.12 系列當日最新的 patch release 也是
[3.12.14](https://www.python.org/downloads/release/python-31214/)（2026-08-12），
兩者一致，因此如實記為 3.12.14 而不是 `3.12`。這代表之後 3.12.15 發佈時，同一個
URL 會改建成新版內容；要更新就重跑 crawl 並改 manifest 的 `version`。

範圍只收 `library/`。tutorial、language reference、c-api、howto、using、FAQ 不在
這次需求（「所有內建模組的文件」）內，指向這些區塊的連結保留絕對 URL，離線環境
點不開，但不會被誤認成已收錄的本地文件。

## 本次需要的兩項 builder 修正

### 1. crawl 的字元編碼（mojibake）

docs.python.org 只送 `Content-Type: text/html`，沒有 charset 參數。requests 對
這種 `text/*` response 依 RFC 2616 退回 ISO-8859-1，`resp.text` 因此把 UTF-8
內文解成 mojibake：第一次抓完的 `os.path.md` 標題裡，原文的 em dash `—`
（U+2014，UTF-8 為 `e2 80 94`）變成三個 Latin-1 字元 U+00E2、U+0080、U+0094。
raw archive 存的就是錯誤解碼後再編碼的 bytes，所以不是 normalize 的問題。

`crawl.py` 改為以 `decode_html()` 取代 `resp.text`：優先用 server 宣告的 charset
（有宣告時行為與原本完全一致），其次用文件自己的 meta charset，最後才退回 UTF-8
（HTML5 預設）；宣告了不存在的 codec 時退回 UTF-8，壞 byte 用 replacement
character。修正後重新 crawl 全部 321 頁，corpus 中 `â€` 類 mojibake 為 0。

既有 collection 的 corpus 沒有受影響：以這類錯誤解碼的指紋（U+0080〜U+009F
C1 控制字元）掃描全部 35,611 個 corpus Markdown，命中 0 個檔案。那些站台都在
header 宣告 charset，而且這次沒有重抓它們；修正只影響之後新抓或重抓的來源。

### 2. 標題內指向本頁的錨點

Sphinx 模組頁的 h1 會把模組名包成指向自己 module target 的 `:mod:` 交叉引用，
docutils 的 `contents` 目錄也會把標題包成 backref anchor，轉成 Markdown 後變成
`# [`typing`](typing.md#module-typing "…")`、`## [Coroutines](asyncio-task.md#id2)`
這種自我連結，並且會污染索引產生的 `section_path`。`normalize.py` 的 `clean()`
改成在 h1〜h6 內把 href 以 `#` 開頭（同頁錨點）的 anchor unwrap，只留標題文字。

修正前 corpus 有 89 個自我連結標題，修正後為 0；唯一一個跨頁的標題連結
（`email.examples.md` 的 `# [`email`](email.md#module-email …)`）依規則保留，
正文內的同頁錨點連結也不受影響。

兩項修正都補了 builder 測試：`builder/tests/test_crawl.py`（6 tests）與
`builder/tests/test_normalize.py`（4 tests）。

  全在 3.12 `library/` 之下，重複 `source_url` 0 筆。

  `Table of Contents` 命中 1 個（`idle.md`），都是正文內容不是 chrome。

- code fence 共 3,010 個，其中 1,710 個沒有語言標記（上游 Sphinx 標為
  `default`/`none`），其餘主要是 `python3`（1,078）、`pycon`（87）、
